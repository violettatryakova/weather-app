# weather-app
Приложение на Python для получения прогноза погоды с функциями ввода названия города, отображения текущей температуры, описания погоды и скорости ветра через OpenWeatherMap.
Не менее 90% запросов к API завершаются успешно и выводят корректные данные. Пользователь получает результат не более чем через 3 секунды после ввода города.
  Цель: разработать MVP консольного приложения для получения прогноза погоды с функциями ввода города и отображения температуры, описания погоды и ветра, обеспечив успешное получение данных без ошибок не менее чем для 90% запросов и повысив удобство использования за счёт понятного интерфейса с подсказками, и сдать готовый проект до 20 мая 2026 года.
Проблема: пользователям командной строки неудобно каждый раз открывать браузер и заходить на погодные сайты, чтобы узнать текущую погоду. Существующие решения либо требуют установки сторонних приложений, либо показывают рекламу. Отсутствует простой и быстрый способ получить прогноз погоды прямо в терминале.
  Целевая аудитория:
1. Студенты технических специальностей — проводят много времени в консоли, хотят быстро узнать погоду
2. Программисты и системные администраторы — предпочитают работать в терминале
3. Пользователи Linux/Mac — привыкли к командной строке
  User Story 1
Как студент, я хочу быстро узнать погоду в любом городе прямо из терминала, чтобы не отвлекаться на открытие браузера.
  User Story 2
Как человек, который часто путешествует, я хочу знать погоду в городах, которые планирую посетить, чтобы взять с собой нужные вещи и правильно спланировать активности.
  Use Case 1: Получение прогноза погоды в текущем городе
· Актор: Пользователь 
· Цель: узнать текущую погоду в выбранном городе
· Основной сценарий:
  1. Пользователь запускает приложение
  2. Приложение выводит приветствие и просит ввести название города
  3. Пользователь вводит название города 
  4. Приложение выводит:
     · Температуру
     · Описание погоды
     · Скорость ветра
  5. Приложение спрашивает, хочет ли пользователь узнать погоду в другом городе
  6. Пользователь выбирает "нет", программа завершается
· Результат: Пользователь получает актуальную информацию о погоде.
  Use Case 2: Повторный запрос для другого города
· Актор: Любопытный пользователь
· Цель: сравнить погоду в нескольких городах
· Основной сценарий:
  1. Пользователь узнал погоду в одном городе
  2. Приложение спрашивает: "Хотите узнать погоду в другом городе?"
  3. Пользователь отвечает "да"
  4. Вводит следующий город
  5. Приложение показывает погоду
  6. Шаги 2–5 могут повторяться несколько раз
· Результат: Пользователь сравнил погоду в разных городах
  Use Case 3: Обработка ошибки "город не найден"
· Актор: Пользователь, который ошибся в названии
· Цель: получить погоду, даже если ошибся в вводе
· Основной сценарий:
  1. Пользователь вводит название города с ошибкой
  2. Приложение не находит город в API
  3. Приложение выводит "Город не найден. Проверьте название."
  4. Приложение снова предлагает ввести город
· Результат: Пользователь понимает ошибку и вводит правильное название
  Use Case 4: Обработка пустого ввода
· Актор: Пользователь
· Цель: получить актуальный прогноз погоды 
· Основной сценарий:
  1. Пользователь запускает приложение
  2. На запрос "Введите город" нажимает Enter, ничего не введя
  3. Приложение выводит "Ошибка: введите название города"
  4. Приложение снова запрашивает город
· Результат: Пользователь вводит название города корректно
  Use Case 5: Обработка отсутствия интернета
· Актор: Пользователь без подключения к сети
· Цель: узнать актуальный прогноз погоды
· Основной сценарий:
  1. Пользователь запускает приложение
  2. Вводит город
  3. Приложение пытается отправить запрос, но нет соединения
  4. Приложение выводит "Ошибка подключения. Проверьте интернет."
  5. Приложение предлагает попробовать снова
· Результат: Пользователь понимает, что нужно проверить интернет
  Use Case 6: Проверка погоды перед выходом из дома
· Актор: Студент
· Цель: решить, брать ли зонт
· Основной сценарий:
  1. Студент запускает приложение утром
  2. Вводит свой город
  3. Видит "Дождь" в описании погоды
  4. Берёт зонт и выходит
· Результат: Студент возьмет зонт и не промокнет под дождем
  Use Case 7: Проверка погоды для планирования активностей
· Актор: Спортсмен
· Цель: решить, идти на пробежку или в зал
· Основной сценарий:
  1. Спортсмен запускает приложение
  2. Вводит свой город
  3. Видит "−15°C, снег"
  4. Решает идти в спортзал вместо улицы
· Результат: Спортсмен выбрал подходящую локацию для тренировки
  Use Case 8: Проверка погоды для пикника
· Актор: Компания друзей
· Цель: решить, ехать на природу или остаться дома
· Основной сценарий:
  1. Пользователь запускает приложение
  2. Вводит место планируемого пикника
  3. Видит "гроза, ливень"
  4. Отменяет поездку, переносит пикник на следующие выходные
· Результат: Компания не промокла и не расстроилась
